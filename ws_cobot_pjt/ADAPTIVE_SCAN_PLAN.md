# 전체 1 mm 스캔 + 이상 영역 0.1 mm 재측정 계획

작성일: 2026-11-16. 사용자 선택에 따라 **현재 블록 `defect_scan`에서 검증한 뒤 차량으로 확장**한다.

구현 상태: 블록용 `adaptive_scan` 진입점, 원시 로그 기반 검출·ROI 마스크 분할, 별도 프로세스 출력, 국부 재측정, 실제 유효 점 기준 병합을 추가했다. 기존 스캔 진입점과 힘제어 기본값은 유지하고, 기록기 주입과 경로 종료 허용오차 설정을 공통 코드에 연결했다. README와 실행 중인 GUI 세션은 변경하지 않았다. 아래 설계 중 저신뢰 후보의 자동 교차 확인과 차량 적용은 후속 범위이며, 현재 저신뢰 후보는 계획에 보존해 검토 대상으로 남긴다. 검증은 오프라인으로 수행했고, 실제 0.1 mm 시뮬레이션 추종은 아직 실행하지 않았다.

컨테이너의 `/workspace`에서 `colcon build --symlink-install --packages-select rokey` 후 `source install/setup.bash`를 실행한다. 탐침을 파지한 가상 세션에서 다음 명령을 사용한다.

```bash
ros2 run rokey adaptive_scan --plan-only       # 경로·설정 확인, ROS 초기화/이동 없음
ros2 run rokey adaptive_scan --coarse-only     # 전체 측정·ROI 계획, 정밀 재측정 보류
ros2 run rokey adaptive_scan                  # 1 mm → ROI 0.1 mm, 기본 PLY
```

`--pointcloud-format plt|ply`, `--rows N`, `--max-fine-minutes N`도 지원한다. 시간 예산은 예상 이동 시간 기준이며 시작한 ROI는 기존 제한 안에서 마치므로 접근·회복 시간까지 포함하는 엄격한 벽시계 상한은 아니다. `--plan-only --from-signals <signals.csv> --centre-mm X Y`는 기존 블록 로그로 ROI를 계획한다. 결과는 `rokey/adaptive_runs/<시각>/`에 기록하고 병합 파일과 출처 CSV를 `rokey/pointcloud/`에도 저장한다. 각 단계 원시 파일은 `signals.csv`, 품질·실행 결과는 `summary.json`이다. RViz 미리보기는 `/dsr01/surface_follow/points`이며 전체 해상도 파일과 별도로 최대 10,000점으로 제한한다.

## 1. 목표와 기본 실행 흐름

```text
HOME / 파지·TCP·기준 좌표 확인
→ 전체 영역 1 mm 스캔
→ 높이·힘·미측정 구간으로 이상 후보 검출
→ 인접 후보 묶기 / ROI 외확장 / 경로·시간 산출
→ 필요하면 불확실 후보를 짧은 교차 경로로 확인
→ ROI만 0.1 mm 재측정
→ 두 해상도 결과 병합 / 판정·미측정 상태 저장
→ 정상 완료 시 HOME
```

1 mm 기준 차량 PLY는 그대로 유지한다. 정밀 데이터는 실제로 다시 움직이며 취득한다. 기준 PLY를 보간해 점 수만 늘리는 작업으로 대체하지 않는다.

## 2. 현재 코드와 연결 범위

현재 `defect_scan.py`의 `RasterPath`는 행 간격을 지정한 연속 왕복 경로를 만들고, `SurfaceRun`이 hybrid 추종을 실행한다. `Recording`에는 매 제어 주기의 위치·힘·innovation·목표 힘·edge 상태가 남는다. `ScanMap`은 유효 측정뿐 아니라 HOP 구간도 분석할 수 있다.

현재 `pitch_mm=1.0`, `spacing=0.0005`, `grid_mm=1.0`은 각각 **행 간격 1 mm / 점 저장 간격 0.5 mm / 그래프 격자 1 mm**로 서로 다르다. 새 작업에서는 단계별 설정을 명시적으로 분리한다.

기존 `defect_scan`, `contact_scrape`, force controller와 `repair_manager`의 호출 흐름은 유지한다. 새 진입점에서 기존 hybrid 제어기를 호출하는 방식으로 추가한다. 단계별 설정은 실행 객체에 전달하고 전역 YAML을 실행 중 덮어쓰지 않는다.

예정 모듈:

```text
rokey/
├── adaptive_scan.py                 신규 CLI / coarse→ROI→fine 작업 조율
├── refinement/
│   ├── detection.py                정상 잡음 모델 / 측정 기반 이상 후보
│   ├── roi.py                      후보 병합·외확장 / ROI 내부 래스터
│   ├── data.py                     단계 결과 / coverage / 해상도 병합
│   └── output.py                   제어와 분리한 로그·점군 출력 프로세스
├── defect_scan.py                  기존 단일 해상도 실행 유지
└── surface_follow/
    ├── controllers.py              기존 hybrid 힘 제어 유지
    ├── runtime.py                  기존 HOME·접촉·이탈·정지 절차 재사용
    └── recording.py                증분 전달과 출력 분리 연결
config/adaptive_scan.yaml           신규 단계별 설정
```

`RobotProgram`과 executor는 작업 전체에 하나를 사용한다. 단계마다 새 `rclpy.init()`을 호출하지 않는다. `SurfaceRun`의 빌려 쓰는 프로그램 방식을 활용하되, 단계 종료 시 해당 단계의 구독·발행자·출력 자원을 정리해 이전 단계의 콜백이 누적되지 않게 한다.

## 3. 단계별 초기 설정안

| 항목 | 전체 coarse | 국부 fine |
|---|---:|---:|
| 행 간격 | 1.0 mm | 0.1 mm |
| 출력 점 간격 | 1.0 mm | 0.1 mm |
| 결과 맵 격자 | 1.0 mm | 0.1 mm |
| 요청 이동 속도 | 4.0 mm/s | **1.0 mm/s** |
| 기본 목표 힘 | 1.5 N | 1.5 N |
| 외부 제어 주기 | 40 Hz | 40 Hz 유지 |

coarse도 이상 판정용 원시 로그는 40 Hz로 취득한다. 1 mm는 출력 점군·탐색 경로의 기준이며, 힘 이벤트를 감지하기 전에 로그까지 1 mm로 버리지 않는다.

fine은 1 mm/s에서 한 제어 주기당 약 0.025 mm 이동하므로 0.1 mm당 약 4개 표본을 기대할 수 있다. 이는 정확도 보장이 아니다. 실제 시간·좌표·상태 신선도를 기록하고 목표 위치에 가까운 **실측 샘플**을 골라 출력한다. 빈 곳을 가상의 독립 측정점으로 채우지 않는다. 원래 타임스탬프 로그도 보존한다.

힘 게인, 안전 한계, watchdog을 해상도에 맞춰 임의로 완화하지 않는다. 접촉·가압·안정화 후 이동하고, 기존 edge/HOP·정지 절차도 적용한다. 취소 시 자동 HOME 복귀를 강행하지 않는다.

## 4. 측정 기반 이상 후보 판정

### 기준 높이와 정상 잡음

블록에서는 유효 접촉 데이터의 정상 구간으로 강건한 기준 평면과 높이 offset을 정한다. 기준 평면을 결함 자체에 맞춰 계속 다시 피팅하지 않는다. fine 단계에서는 ROI 안의 정상 테두리로 기준의 이동·드리프트를 확인한다. **접촉 중 힘 영점을 다시 잡지 않는다.**

정상 구간의 높이, 힘 오차, 접선력, 정규화 innovation 분포를 확보하고 median/MAD 또는 실측 분위수로 초기 임계값을 정한다. 3σ 수준은 후보 민감도 검토의 시작값일 뿐, Kalman 모델의 sigma가 실제 오탐 확률을 보장한다고 가정하지 않는다. coarse와 fine의 속도가 다르므로 정상 분포도 구분해 검토한다.

### 사용할 신호

| 증거 | 후보 의미 | 처리 |
|---|---|---|
| 기준 대비 높이·국부 높이 기울기 변화 | 함몰·돌출·단차 가능성 | 안정된 유효 접촉 표본에서 계산 |
| `abs(innovation) / sigma` 증가 | 예상하지 못한 힘 변화 | 단일 최대값뿐 아니라 위치·주변 표본·재현성 확인 |
| 법선 힘 오차와 접선력 변화 | 걸림·급경사·마찰 변화 가능성 | 목표 힘 변경·감가속·edge 상태를 함께 사용 |
| edge, UNLOAD, 접촉 소실, HOP | 관측 신뢰도 저하 또는 스캔 누락 | 손상 확정과 별개로 재확인 후보 |

여러 인접 셀에서 일관된 높이 변화가 있거나, 같은 위치에 복수 힘 증거가 겹치면 우선 ROI로 선정한다. 단일 짧은 spike는 결함으로 바로 확정하거나 무조건 삭제하지 않는다. 낮은 신뢰 후보로 남기고 필요하면 짧은 교차 경로를 한 번 측정해, 재현되는 경우 정밀 ROI로 올린다. 이렇게 해야 한 번의 잡음마다 큰 정밀 ROI가 생성되는 것을 줄일 수 있다.

`Recording.points`의 힘/자세 필터를 통과하지 못한 표본에도 실제 이상 증거가 있을 수 있다. 검출기는 저장된 PLY만 읽는 대신 전체 원시 로그와 유효성 플래그를 사용한다. 다만 접촉 불량 표본을 정상적인 형상 측정으로 취급하지 않는다.

### 정답 정보 분리

검출기와 ROI 계획기의 입력에는 측정 로그, 정상 기준 평면/메쉬, 작업 경계만 전달한다. `DefectBlock`의 crack/dent 위치나 `scene_truth.json`은 전달하지 않는다. 현재 그래프의 정답 윤곽·볼 추종 이론선은 사후 평가에만 사용한다.

## 5. ROI 생성과 정밀 경로

1. 후보를 블록 로컬 1 mm 셀로 집계하고, 인접 후보를 연결 영역으로 묶는다.
2. 후보의 관측 불확실성과 탐침 반지름을 고려해 정상 테두리를 포함하도록 외확장한다. **초기 padding은 약 2.5 mm**로 제안하고 실측 위치 오차로 조정한다.
3. 중첩 ROI의 정밀 측정 범위를 합쳐 같은 영역을 반복 측정하지 않는다. 블록 경계와 기존 안전 여유 안으로 제한한다.
4. 가늘고 긴 결함을 지나치게 큰 사각형 하나로 감싸지 않는다. 작은 패치 또는 ROI 마스크의 행별 구간으로 나눠 불필요한 정상 영역 스캔을 줄인다.
5. fine 경로는 0.1 mm 간격으로 만들고, 긴 결함에는 가로지르는 방향의 측정이 포함되게 한다.
6. ROI 사이 이동은 기존 안전 높이 접근·이탈을 사용한다. 초기 구현은 기존 HOME 절차도 그대로 재사용하고, ROI 간 HOME 생략 같은 이동 최적화는 후순위로 둔다.

HOP·힘 제어 실패로 건너뛴 구간은 `unmeasured`로 남긴다. 그 영역을 다시 측정해도 기존 힘 한계에서 접근할 수 없다면 `partial` 또는 `unobservable`로 보고한다. 더 큰 힘으로 밀어 넣거나 무한 재측정하지 않는다.

ROI 계획에는 ID, 좌표계, 경계/마스크, 후보 사유, 신뢰도, padding 포함 면적, 예상 이동 거리·시간을 저장한다. `--plan-only`에 해당하는 선택 실행은 ROI와 예상 비용만 출력하도록 계획한다. 실제 이동 전 필수 수동 승인 단계로 만들지는 않는다.

## 6. 출력 비용을 제어 루프에서 분리

선행 오프라인 측정에서 전체 55만 점을 PointCloud2로 구성하는 데 약 422 ms가 걸렸다. 현재 100 ms 스케줄 한계와 150 ms watchdog을 넘으므로, 정밀 단계 구현 전에 출력 경로를 분리한다.

- 제어 루프는 짧은 상태 기록과 점 증분을 비차단 방식으로 전달한다. 전체 점군을 매번 구성하지 않는다.
- 점군 구성·직렬화·시각화 발행은 별도 프로세스로 분리한다. Python 리스트 처리의 GIL 경쟁을 줄인다.
- 화면용 데이터는 다운샘플링하고 오래된 시각화 요청은 합쳐 처리한다. 원본 계측 데이터와 화면용 데이터를 구분한다.
- 원시 로그와 전체 해상도 데이터는 청크 단위로 저장해 Python 딕셔너리를 수십만 개 계속 쌓지 않는다.
- 계측 저장 큐가 지속적으로 포화되면 데이터가 누락된 채 성공 처리하지 않는다. 누락 상태를 기록하고 정상 정지 절차로 종료한다. 기존 로봇 힘 한계는 그대로 둔다.

## 7. 두 단계 데이터 병합

```text
adaptive_runs/<run_id>/
├── manifest.json                   Tool/TCP/기준좌표/단계 설정/참조 버전
├── coarse/
│   ├── cloud.ply                   1 mm 출력 점군
│   └── measurements.*              타임스탬프 원시 기록과 유효성
├── roi_plan.json                   ROI·원인·경계·예상 비용
├── fine/roi_<id>/
│   ├── cloud.ply                   실제 0.1 mm 국부 측정
│   ├── measurements.*
│   └── result.json                 재현·미재현·부분 측정·측정 불가
└── merged.ply                      실제 측정 범위에 따른 혼합 해상도 결과
```

좌표는 블록/차량 로컬 ROI 계획을 BASE로 변환해 같은 `base_link`, m 단위로 저장한다. 기존 PLT/PLY 선택 기능도 유지한다.

fine에서 **실제로 유효 측정된 부분**만 coarse 점을 대체한다. ROI 사각형 전체를 지워 HOP 구간까지 사라지게 하지 않는다. fine이 비어 있으면 coarse 또는 미측정 상태를 유지한다. 원본 coarse 파일은 보존하고, 병합 결과에는 해상도·단계·ROI 출처를 추적할 메타데이터를 함께 남긴다.

fine에서 신호가 재현되지 않았다고 곧바로 정상으로 확정하지 않는다. 속도 의존성, 팁의 균열 bridging, 측정 누락을 구분해 판정한다.

## 8. 예상 시간과 운영 방식

면적 A, 행 간격 p, 이동 속도 v일 때 주 이동 시간은 대략 `A/(p*v)`이다. coarse는 p=1 mm, v=4 mm/s, fine은 p=0.1 mm, v=1 mm/s이므로 다음 관계가 성립한다.

```text
T_fine / T_coarse ≈ 40 × (padding 포함 ROI 총면적 / 전체 면적)
```

| 외확장·중복 제거 후 ROI 면적 비율 | coarse 대비 fine 추가 시간 |
|---:|---:|
| 1% | 약 0.4배 |
| 5% | 약 2배 |
| 10% | 약 4배 |

74×74 mm 블록의 coarse 이상적 시간은 약 23분이다. 예를 들어 **10×10 mm 정밀 패치 하나**는 약 10,201점, 이동 약 1.02 m, 1 mm/s에서 약 **17분**이 추가된다. 접근·안정화·회복 시간은 별도다. 0.1 mm를 낮은 속도로 수행하므로, 작은 ROI라도 즉시 끝나는 것은 아니다.

후보가 너무 많을 경우 정상 잡음·참조 정합 문제인지 먼저 판단한다. 계획 결과에 예상 비용을 표시하고, 사용자가 설정한 시간 예산이 있다면 미실행 ROI를 `pending`으로 남긴다. 기본 동작에서 임의로 이상 영역을 누락시키거나 ROI를 계속 확대하는 재귀 스캔은 하지 않는다.

## 9. 구현·검증 순서

1. **오프라인 후보 검출과 ROI 계획**: 기존 로그를 재생하고 작은 합성 정상/함몰/단일 잡음 데이터로 판정을 확인한다. 로봇 이동은 하지 않는다.
2. **출력 프로세스 분리**: 제어 루프 안에 전체 PointCloud2 생성이 남지 않게 하고, 로그 큐와 최종 파일의 누락 여부를 확인한다.
3. **새 단계 조율 진입점**: coarse → ROI → fine을 단일 프로그램에서 실행하고 기존 hybrid 제어기와 HOME·정지 절차를 연결한다.
4. **짧은 블록 국부 검증**: 대표 이상 영역 1~2개만 재측정한다. 실제 유효 점 간격·coverage, 힘 RMSE/피크, 주기 지연, 로그 보존과 ROI 중복 제거를 확인한다. 모서리·HOP 구간은 측정 불가/부분 측정 상태까지 검증한다.
5. **차량으로 확장**: 우선 도달 가능한 보닛 등 상면으로 제한한다. `vehicle.json`의 BASE↔차량 변환을 한 작업 동안 고정하고, 원본 DAE 메쉬의 국부 표면/법선으로 signed normal residual을 계산한다. 곡면에 전역 평면이나 단순 z 차이를 적용하지 않는다. 1 mm PLY의 최근접 점 거리만으로 0.1 mm 결함을 판정하지 않는다.

검증 보고에는 ROI 검출 결과, 미측정 영역, fine 유효 coverage·실제 점 간격 분포, native 힘 피크·주기 지연, 시간·점 수·파일 크기를 남긴다. 시뮬레이션 정답과의 비교는 결과 평가 단계에서만 수행한다.

## 10. 보장하지 않는 범위

1 mm coarse 경로가 모든 0.1 mm 결함을 발견한다고 보장할 수는 없다. 행 사이의 작은 결함이나 구형 팁이 걸쳐 지나가는 균열은 후보가 생성되지 않을 수 있다. 필요하면 coarse 교차 방향 확인 또는 별도 센서와 결합하는 정책을 추가로 선택해야 한다.

0.1 mm는 경로·저장 간격 목표다. 현재 팁 반지름 1.5 mm, TCP 보정, 접촉 변형과 센서 시간 응답의 한계는 별도로 남는다. 정밀 스캔 점 수가 늘어나는 것을 0.1 mm 형상 정확도 확보로 보고하지 않는다. 차량 전체 하부·측면의 자동 도달/충돌 계획과 실기 적용은 첫 블록 검증 범위에 포함하지 않는다.
