# 2D 표면 추종 모델 검토

기존 `smooth`, `corners`, `mixed`, `wall` 단면 형상은 유지했다. 변경 범위는 `practice`이며 실제 로봇, ROS 노드, Gazebo 설정은 변경하지 않았다. 이 모델은 로봇의 입출력 특성을 반영한 **2D Cartesian 대체 모델**이다. M0609의 관절 동역학이나 제조사 내부 힘제어기를 재현한 것은 아니다.

## 환경을 맞춘 범위

| 항목 | robot 기본값 | 근거 / 의미 |
|---|---:|---|
| 물리 계산 | 500 Hz | `../native/model_export.py`의 Gazebo `max_step_size=0.002` |
| 힘 센서 표본 | 200 Hz | 같은 파일의 force-torque 센서 주기 |
| 상태 전달 | 60 Hz | `../native/session.py` 전달 루프 |
| 명령 참조 갱신 | 100 Hz | `../native/virtual_force.yaml`의 backend 주기 |
| 외부 추종 제어 | 40 Hz | 이 실험에서 선택한 주기. 실제 로봇 서비스 처리율을 측정한 값은 아님 |
| 힘 필터 시정수 | 80 ms | `../native/virtual_force.yaml`의 `wrench_filter_time` |
| 팁 반지름 / 목표 힘 / 요청 속도 | 1.5 mm / 1.5 N / 5 mm/s | `../ws_cobot_pjt/src/rokey/config/robot.yaml` |
| 이동 가속도 / 각속도 / 각가속도 제한 | 100 mm/s² / 60°/s / 120°/s² | 같은 로봇 설정의 scan/motion 값 |
| 어드미턴스 M / D | 8 kg / 800 Ns/m | virtual-force 설정의 병진축 값. 2D 적용 시 안정성을 별도 검토해야 함 |

다음 값은 실측값이 아니라 조절 가능한 가정이다: 유효 질량 1 kg, 관성 0.003 kg·m², 위치 강성 2500 N/m, 감쇠 100 Ns/m, 구동 응답 15 ms, 상태 지연 20 ms, 명령 지연 15 ms, 지터 ±3 ms, 상태 갱신 누락 1%, 힘 잡음 표준편차 0.025 N. 유효 질량은 탐침의 payload 질량과 다르다. 갱신 누락은 TCP 패킷 손실 자체를 뜻하지 않는다.

검색 속도 3 mm/s, 접촉 확인 0.3 N 등은 이 모델의 보수적인 실험값이다. 로봇 설정 전체를 그대로 복사한 것은 아니다. `ideal` 프리셋은 지연·잡음 등을 줄인 비교용이며, 이전 버전의 동작을 완전히 복원하지는 않는다.

## 데이터와 제어 흐름

```text
main.py
└── surface_lab/simulation.py : 서로 다른 주기의 실행 및 상태 전이
    ├── geometry.py          : 기존 단면, 힘/이동 이력 기반 법선 추정
    ├── physics.py           : 팁·축 충돌, 유한 강성/응답의 구동 모델
    ├── io_model.py          : 센서 표본화·영점·필터, 지연 전달, 명령 유지/만료
    ├── control.py           : 하이브리드 / 어드미턴스 추종
    │   └── safety.py        : 빠른 힘 경로와 증가율 기반 과부하 예측
    ├── recording.py         : CSV, 위치점, 요약 JSON
    └── viewer.py            : 로컬 시각화와 조절 패널
review_sensitivity.py        : 명시적으로 실행하는 제한된 비교 실험
```

제어기는 같은 센서 표본 시점의 위치·속도·각도·힘을 묶은 상태를 지연 수신한다. 수신 시각과 원본 표본 시각을 구분하며, 실제 경과 시간으로 계산한다. 500 Hz 물리 계산에서 40 Hz 제어를 정수 나눗셈으로 근사하지 않는다. 센서와 각 루프는 물리 시간 격자에 맞춰 실행되므로 일부 주기는 2 ms 단위로 교대로 달라진다.

처음 0.4초는 비접촉 상태에서 영점을 잡는다. 힘에는 센서 방향에 따른 바이어스, 선택적인 드리프트, 잔여 관성 보상 오차와 잡음을 추가한다. 이후 영점은 고정한다. 일반 힘 피드백은 80 ms 필터를 사용하고, 급격한 힘 증가 감지는 별도 12 ms 경로를 사용한다. 법선 추정에도 별도 15 ms 벡터 필터를 사용하여 느린 힘 필터 때문에 모서리에서 방향 추정까지 늦어지는 문제를 줄인다.

제어기에 단면의 정답 법선이나 충돌 위치/충돌체 ID를 제공하지 않는다. 화면과 기록의 `true_*`는 검증 전용이다. 단면 정보는 초기 배치와 실험 종료 경계에도 쓰인다.

## 민감도와 오버슈트 대응

1. **접촉과 가압을 분리한다.** `TARE → SEARCH → CONFIRM → SETTLE → TRACK` 순서로 시작한다. 접촉 후 목표 힘까지 램프로 올리고, 힘이 안정된 다음 전진한다. 운전 중 목표 힘 변경도 변화율을 제한한다.
2. **명령을 실제 구동기처럼 제한한다.** 명령 지연·유지·만료, 참조 속도/가속도, 각속도/각가속도, 힘 명령 변화율과 구동 응답을 적용한다. 하이브리드의 가압 방향은 즉시 바뀌는 추정 법선 대신 현재 탐침 축을 따른다.
3. **포화 시 적분을 누적하지 않는다.** 하이브리드 PI에 조건부 적분을 사용한다. 어드미턴스는 implicit Euler 적분, 법선 속도 제한, 위치 참조 오차 제한을 적용한다. 참조가 제한에 걸리면 더 밀어 넣는 적분을 멈춘다.
4. **지연과 힘 증가율을 보고 미리 감속한다.** 현재 빠른 힘과 증가율로 명령 도착 이후의 힘을 추정한다. 추정 법선과 탐침 축의 오차가 커져도 전진 속도를 줄인다. 추가로 힘 여유와 예상 정지 거리를 이용해 속도를 제한한다.
5. **과부하는 제한된 후퇴 후 재접촉한다.** `UNLOAD → RECOVER → CONFIRM → SETTLE → TRACK`으로 복귀한다. 후퇴/재접촉에는 시간·거리 제한이 있고, 진전 없이 과부하가 반복되면 중지한다. 끝없는 재시도는 하지 않는다.
6. **정지 요청과 정지 확인을 구분한다.** 오래된 상태, 명령 만료, 측정 힘 8 N 초과, 팁 접촉과 맞지 않는 힘/모멘트 관계는 제동으로 연결한다. 정지 요청 시 대기 명령을 비우고 가압을 해제한다. 로컬 속도뿐 아니라 정지 요청 이후의 새 원격 피드백에서 속도·각속도·접촉 하중 감소가 확인되어야 `stop_confirmed=true`가 된다. 통신이 끊겨 확인할 수 없으면 확인 실패로 남긴다.

속도 제한은 다음 가정으로 계산한다. `T`는 상태 지연 + 명령 지연 + 구동 응답 + 제어 주기 + 지터 여유, `d`는 힘 여유를 가정한 접촉 강성으로 나눈 허용 이동량, `a`는 가정한 제동 감속도이다.

```text
v·T + v²/(2a) ≤ d
v_limit = min(requested_speed, a·(sqrt(T² + 2d/a) − T))
```

기본 강성 상한 가정은 3500 N/m, 제동 감속도 가정은 0.08 m/s²이다. 식 자체가 로봇 안전을 보증하지는 않는다. 실제 접촉 강성이 더 높거나, 실제 감속 성능이 낮거나, 지연이 가정을 넘으면 유효하지 않다. 미지의 급경사를 만날 수 있으므로 평탄 구간에서도 보수적으로 느려질 수 있다.

힘/모멘트 일관성 검사는 팁 위치와 탐침 길이로 예상한 모멘트를 측정 모멘트와 비교한다. 축 접촉 가능성을 검출하는 보조 수단이며 모든 비정상 접촉을 식별하지는 못한다.

## 제한된 비교 결과

기존 `mixed` 단면에서 시작점부터 약 425 mm, **측정 X=460 mm까지** 비교했다. 단면 전체나 모든 자세에 대한 검증이 아니다. 목표 힘은 1.5 N, 요청 전진 속도는 20 mm/s로 동일하다. 보호 로직은 실제 속도를 줄이므로 동일 실제 속도의 성능 비교는 아니다.

- 기본 조건: 위 `robot` 기본값.
- 지연 증가: 상태 60 ms, 명령 30 ms, 지터 ±10 ms, 갱신 누락 3%, 힘 필터 120 ms.
- 비교 기준: 지연 증가 조건에서 적응 감속/후퇴만 해제. 하드 중지, watchdog, 적분 포화 제한은 유지.
- 힘 최대값은 접촉력 벡터 크기이다. RMSE는 `TRACK` 중 지연·필터된 법선 힘 기준이므로 순간 충돌의 크기를 대신하지 않는다.

## 사용

```bash
cd /Users/wonjun/Desktop/wonjun/ws_cobot_pjt/practice
./run.sh
```

- `F1` / `F2`: ideal / robot 프리셋으로 새 실험.
- `H` / `A`: 하이브리드 / 어드미턴스로 새 실험.
- `1` ~ `4`: 기존 단면 선택, 새 실험.
- `I/O delay` 패널: 힘 필터, 상태/명령 지연, 지터, 갱신 누락 조절.
- `Space`: 제동을 확인한 뒤 일시정지, 다시 누르면 재접촉/안정화 후 진행.
- `Gains`: robot 모드에서 일시정지 확인 후 변경.
- `P`: 아래 방향 1.5 N, 120 ms 외란.
- `R`: 초기 상태로 새 실험. `S`: 현재 결과 저장.

```bash
# 지연이 큰 조건을 화면에서 관찰
./run.sh --controller admittance --speed-mm-s 20 \
  --feedback-delay-ms 60 --command-delay-ms 30 --jitter-ms 10 \
  --dropout 0.03 --sensor-tau-ms 120

# 별도로 선택해서 실행하는 비교 실험: 6가지 경우만 수행
./.venv/bin/python review_sensitivity.py
```

`--no-adaptive`는 비교 목적이다. `--effective-mass`, `--noise`, `--bias-y`, `--drift-y`, `--inertia-error`로 가정의 민감도를 더 살펴볼 수 있다. `--time-scale`은 화면 재생 배속이며 시뮬레이션 안의 상대적인 주기를 바꾸지 않는다. 실행 중인 이전 창에는 변경 코드가 반영되지 않으므로 다시 실행해야 한다.

## 실제 로봇으로 옮기기 전 남은 한계

- 접촉은 Pymunk의 강체 충돌/충격량이다. 식에 넣은 강성 상한과 실제 물리 접촉을 같은 것으로 보면 안 된다. 탄성·변형·탐침 휨·센서 대역폭을 식별한 접촉 모델이 추가로 필요하다.
- 200 Hz 힘 관측보다 짧은 충격은 구간 평균에 묻힌다. 표의 500 Hz 최대값이 더 큰 이유이다. 8 N interlock도 측정값 기반이라 짧은 피크를 놓칠 수 있으며, 실제 로봇 펌웨어의 보호 기능을 구현했다고 볼 수 없다.
- 관절별 관성, IK/특이점, 자세별 유효 질량, RG2 전체 충돌, 6축 손목 힘/모멘트와 중력 보상을 재현하지 않는다. 힘에만 간단한 보상 잔차를 넣었고 모멘트 센서의 바이어스·잡음·완전한 동역학은 모델링하지 않았다.
- 마찰과 접선력이 섞인 힘만으로 법선을 유일하게 알 수는 없다. 급격한 모서리에는 단일 법선 자체가 정의되지 않을 수도 있다. 감속·정지·재접촉이 필요한 상황을 자세 회전만으로 해결할 수는 없다.
- 지연/유효 질량/접촉 강성/정지 거리/힘 잡음을 실제 로그로 식별하고, 로봇 내부의 빠른 힘제어 또는 지원되는 실시간 명령 경로에 연결해야 한다. Python 서비스 호출의 응답률을 확인하지 않고 이 주기를 그대로 요구하면 안 된다.

현재 결과는 오버슈트와 제어 실패 가능성을 낮추는 구조를 보여준다. 오버슈트가 없어졌거나 실제 로봇에서도 같은 힘/정지 성능이 보장된다는 의미는 아니다.
