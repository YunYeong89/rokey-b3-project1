# 2026-11-19 진행 사항

실기 보닛 스캔을 DSR `mesh-height`와 연속 스트림 `mesh-height-stream`으로 실행하고, 실제 dent·crack 위치를 기준으로 검출 성능을 확인했습니다. 커밋은 아직 하지 않았습니다.

## 1. 요약

| 항목 | 상태 |
|---|---|
| 실기 `mesh-height` (DSR movesx) | 구현 완료, 실행 확인 |
| 실기 `mesh-height-stream` (RT 관절 서보) | 실행 확인. 경로 1 완료(114347). 1.5 N 정지 문제는 수정 후 재실행 대기 |
| 탐침 거치대, v3 5 mm 탐침 | 실기 장면과 가상 `--car demo`에 반영 |
| 힘 오프셋 물리 모델 (`force_model`) | 구현 완료, 실측 실행 대기 |
| dent 검출 | 원시 데이터에서 두 패스 모두 확인(−0.21 mm). ROI 단계는 놓침 |
| crack 검출 | 5 mm 탐침으로는 높이로 검출 불가(기하적 한계) |

## 2. 실기 mesh-height (DSR)

**구현**: `part_scan/height_dsr.py`의 `MeshHeightDsr`

**동작 순서**
1. 첫 점 위 접근 위치에서 2 s 정지
2. 정지 상태 힘을 0점으로 기록
3. 위치 제어로 4 mm/s 하강. 상승 힘 0.5 N이 2회 연속이면 접촉 후보로 봄
4. 0.2 s 정지 확인(10회 평균) 뒤 접촉 확정
5. 접촉한 TCP 높이를 기준으로 계획 경로 전체를 옮김
6. 임피던스 깊이 = (누름 힘 + 정지 측정값) / z 강성 만큼 더 내려서 진행
7. movesx 최대 100점 단위, 점 간격 1 mm 이상으로 등속 이동

**오늘 고친 문제**

| 증상 | 원인 | 수정 |
|---|---|---|
| 들어 올린 이동이 NOT REACHABLE | 바깥 도달 범위 근처 | 보닛 `travel_margin_mm` 확인 추가 |
| 매번 계획 캐시 미스 | 펜던트 TCP 읽기 노이즈 | 정의 TCP 사용 |
| 26.8 N으로 누름 | 메쉬 절대 z를 목표로 사용 | 접촉 높이 기준 경로 + 임피던스 깊이 |
| 표면 5.7 mm 위에서 접촉 판정 | 이동 중 힘 노이즈 | 정지 확인 단계 추가 |
| 1–2 mm 떠서 이동 | 컴플라이언스 전환 후 기준 높이 사용 | 위치 제어 상태의 접촉 높이를 기준으로 사용 |

**차량 높이**: `real_scene.yaml`의 `vehicle.base_z_mm`를 78.73에서 82.36으로 올림(실측 접촉 높이 평균 +3.63 mm).

## 3. TCP

| 실행 | 검출 TCP | 설정 위치 |
|---|---|---|
| DSR `mesh-height` | 282.5 mm (283.0에서 0.5 mm 줄임) | `real_scene.yaml` `probe.tcp_mm_deg` |
| `mesh-height-stream`, `mesh-normal-stream` | 283.0 mm | `real_scene.yaml` `probe.stream_tcp_mm_deg` |

- 펜던트 값을 읽지 않고 위 정의값으로 검출합니다. 컨트롤러 활성 TCP(283.0)와의 차이는 `ContactProbe.offset`으로 명령과 측정 위치에서 변환합니다.
- TCP를 0.5 mm 바꿔도 ROI는 같은 패스 안의 주변 고리를 기준으로 비교하므로 결과가 달라지지 않는 것을 확인했습니다.

## 4. 실기 mesh-height-stream 수정

실기 스트림 백엔드(`part_scan/real_cartesian.py`)를 실제로 실행하면서 아래 문제를 차례로 고쳤습니다.

| 증상 | 원인 | 수정 |
|---|---|---|
| `Cartesian stream unavailable` | RG2 `grip_detected`가 false. 탐침은 잡혀 있었음(폭 28.6 mm) | 그리퍼 신호 조건 제거, `probe_attached`는 항상 true |
| 시작 0.4 s 만에 정지 | 컨트롤러 자세와 URDF 자세가 2.02 mm 차이, 허용치는 2 mm | 스트림 위치를 측정 관절값의 URDF 계산값으로 보고 |
| 진행 판정이 계속 '대기' | 위 2 mm 차이가 진행 허용치 0.8 mm보다 큼 | 위와 같은 수정으로 해결 |
| 접촉 직후 −5.5 mm/s로 눌러 6.5 N | 접촉 후 위치 기준이 계획된 절대 높이로 내려감 | 접촉 순간 서보 기준 위치로 경로를 TCP 축 방향으로 옮김(`mesh_run.py`) |
| 1.5 N에서 16.6 s 만에 정지 | 정지 조건이 x·y·z 합친 힘 4 N. 행 끝에서 마찰 Fy −2.8 N, Fz 3.6 N | 정지 판정을 누르는 축 방향 힘으로, 한계는 5.0 N(필터 없는 합친 힘 10 N은 유지) |

**실행 기록**

| 실행 | 누름 힘 | 결과 |
|---|---|---|
| 114347 | 0.7 N | 경로 1 완료. 경로 2는 616.8 s 중 451.5 s에서 종료. 접촉 유지율 89% / 62% |
| 122243 | 1.5 N | 접촉 유지율 98.8%, Fz 중앙값 1.44 N. 16.6 s에서 힘 한계로 정지 → 위 표 마지막 줄로 수정 |

**현재 스트림 설정** (`robot.yaml`)
- 누름 힘 `mesh_height.force_n` 1.5 N (DSR `mesh-height`와 공유). `mesh_normal.force_n`은 0.7 N 유지
- 접촉 확인 0.3 N 이상 0.12 s 유지
- 정지 한계 `real_stream.max_force_n` 5.0 N(누르는 축 방향)
- 검출 속도 4 mm/s

## 5. 탐침 거치대와 탐침

- 팀 3D-models 레포의 거치대 STL을 `meshes/probe_holder.stl`로, 탐침 v3 5 mm를 `meshes/probe_v3_5mm.stl`로 반영했습니다.
- 거치대 위치: `holder_pose_base_mm_deg: [350, -150, 0, 0]`
  - 로봇 쪽 나사 구멍 중심이 BASE (275, −150)에 오고, 긴 변이 +x 방향입니다.
- 계획 시 충돌 상자(`rack_box_mm`)로 쓰고, RViz 마커로 표시합니다.
- 가상 `./run_virtual.sh --car demo`도 같은 거치대 위치와 탐침으로 맞췄습니다.

## 6. 힘 오프셋 보정 (구현만, 검출에는 미적용)

- `motion_offset`: 상하좌우로 움직이며 오프셋을 측정하는 보정 프로그램입니다. 사용자 요청으로 mesh-height 적용은 뺐습니다.
- `motion_offset_check`: 힘제어 없이 계획 경로를 공중에서 따라가며, 보정 전후 힘을 subplot으로 비교합니다.
- `home_pose`: 어느 위치에서든 힘제어를 해제하고 위로 올라간 뒤 HOME으로 복귀합니다.
- `force_model` (학습 없는 물리 모델)
  - 관절 토크 모델(J⁻ᵀ): 오프셋, 마찰, 점성, 이력, 관절 관성, 링크·공구 중력
  - 칼만 필터 층
  - 축별 그래프: 원시 힘, 물리 모델 적용, 칼만 적용
  - 수집 동작은 tool0 300 mm 이상, TCP 200 mm 이상, 아래쪽(−z) 동작 없음, 거치대 회피 조건으로 계획
  - 판정과 선택은 z축만 사용합니다(x·y 이상치는 로직에 영향 없음).

## 7. dent·crack 검출 분석

**결함 위치** (`hood_damaged` STL을 공칭 보닛에 정합해 BASE로 변환)
- dent: (566.7, +9.3), 깊이 0.47 mm, 폭 5–7 mm
- crack A: x 578–598, y +3 ~ +7, 깊이 0.25 mm, 폭 약 1 mm
- crack B: x 555–573, y −7.5 ~ −9.9
- 정합에 y 부호 모호성이 있지만, 측정 데이터는 "정합한 그대로" 쪽을 지지합니다.

**DSR 실행 110422** (0.7 N, 4 mm/s)
- dent 위치에서 −0.06 mm의 약한 오목함만 보임
- crack은 신호 없음. 높이 노이즈 0.16 mm

**스트림 실행 114347** (0.7 N)
- ROI 확정 0개, 미확정 후보 12개. dent 위치에 있는 후보는 없음
  - 5개(x ≈ 603.6)는 경로 2 행 끝 회전 구간의 접촉 끊김
  - 5개(578–585, −17 ~ −27)는 결함이 없는 곳
  - crack 근처 2개(roi_007: crack B에서 1.6 mm, roi_012: crack A에서 3.0 mm)는 깊이 0.15 / 0.06 mm로 노이즈 수준
- 원시 데이터 분석(25 mm 중앙값 평탄화 후, 반경 2.5 mm 원 평균 − 4.5–8 mm 고리 평균)
  - 두 패스 평균에서 **(567.5, 11.0)에 −0.21 mm 오목함**. 이 지도 노이즈의 4.3배이고, 가장자리를 빼면 가장 깊음
  - 정합 dent 위치와 1.9 mm 차이. 경로 1(−0.23 mm)과 경로 2(−0.27 mm)에서 각각 나타남
  - y 부호를 뒤집은 위치는 −0.03 mm로 신호 없음
  - DSR 실행보다 약 3배 선명함
- ROI가 dent를 놓친 이유
  - 샘플 노이즈 0.16 mm. 한 패스 기준(깊이 0.15 mm, 4σ)으로는 0.1–0.15 mm인 dent가 통과하지 못함
  - 두 패스 교차 확인 샘플이 0개(`cross_pass_samples`)

**crack의 한계**
- 반경 2.5 mm 공이 폭 1 mm 홈에 들어가는 최대 깊이는 약 0.05 mm로, 노이즈보다 훨씬 작습니다.
- 2 mm 탐침(반경 1 mm)이어도 0.13 mm입니다.

## 8. 남은 일

1. 1.5 N, 축 방향 5 N 한계로 `mesh-height-stream` 재실행. 접촉 유지율과 높이 노이즈(마찰 증가 영향) 비교
2. ROI에 두 패스 평균 오목함 판정 추가(원 − 고리 대비, 행 끝·가장자리 제외). 제안만 하고 미구현
3. crack: 탐침 교체나 다른 신호(마찰 등) 검토 필요. 지금 탐침으로는 검출 대상에서 빼는 것이 현실적
4. `mesh_normal.force_n`(0.7 N)을 1.5 N에 맞출지 결정
5. `force_model_collect` 실측 실행과 결과 확인
6. 변경 사항 커밋

## 9. 명령어

```bash
# 실기 스캔
ros2 run repair_car real_scan --part bonnet --controller mesh-height            # DSR movesx
ros2 run repair_car real_scan --part bonnet --controller mesh-height-stream     # RT 관절 서보 스트림
ros2 run repair_car real_scan --part bonnet --controller mesh-height-stream --plan-only   # 계획만

# 보조 프로그램
ros2 run repair_car home_pose
ros2 run repair_car motion_offset
ros2 run repair_car motion_offset_check
ros2 run repair_car force_model_collect
ros2 run repair_car force_model_fit
ros2 run repair_car force_model_view

# 가상 데모
./run_virtual.sh --car demo
```
